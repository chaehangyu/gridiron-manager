## 1. 개요

### 1.1 한 줄 정의
플레이어는 NFL 팀의 **단장 겸 감독**이 되어 **로스터·뎁스차트를 관리하고 공수 전술을 설계**한다. 경기는 **플레이 단위로 자동 시뮬레이션**되며, 결과는 선수 능력치와 **전술 선택의 상성**에 의해 결정된다.

### 1.2 핵심 재미 (Design Pillars)
1. **전술이 결과를 바꾼다** — 같은 로스터라도 전술 설정에 따라 경기 결과가 체감될 만큼 달라져야 한다.
2. **선수가 살아있다** — 능력치, 컨디션, 부상, 기록이 누적되어 각 선수에게 이야기가 생긴다.
3. **이유를 알 수 있다** — 이겼든 졌든 "왜"를 박스스코어·드라이브 요약·전술 리포트로 추적할 수 있다.
4. **빠른 루프** — 한 주차(준비→시뮬→결과 확인)를 수 분 안에 끝낼 수 있다.

### 1.3 레퍼런스
| 게임 | 참고할 점 |
|------|-----------|
| Football Manager (SI) | 능력치 1–20 표기, 전술 화면, 인박스 중심 UI, 경기 텍스트 중계 |
| Front Office Football | 미식축구 매니지먼트의 깊이, 게임플랜 성향 설정 방식 |
| Madden NFL Franchise | 뎁스차트, 포지션별 능력치 구성 |
| Football GM (ZenGM) | **경기 진행 골격 코드 포팅 대상** (시계·페널티·교체·특수팀), 선수 데이터 구조, 부상 규칙 |
| nflverse | 실제 데이터 전반 + 기대득점·승률 모델 + 타이브레이커(nflseedR) + 4th down 모델(nfl4th) |

## 3. 목표와 비목표

### 3.1 MVP 목표
- G1. 32개 팀 · 실제 선수로 구성된 NFL 정규시즌 17경기 + 플레이오프 + 슈퍼볼을 **끝까지 플레이 가능**.
- G2. 사용자 팀의 **뎁스차트와 전술을 설정**하고, 그 설정이 **경기 결과 통계에 측정 가능한 영향**을 준다.
- G3. 시뮬레이션 결과가 **실제 NFL 평균 통계와 비슷한 범위**에 들어온다 (§8.4 보정 목표).
- G4. 모든 진행은 **저장/불러오기** 가능.
- G5. **부상이 시즌 운영의 핵심 변수**가 된다. 부상 대응(교체, 강행 출전, IR 활용, 로테이션)이 성적에 영향을 준다.
- G6. **매주 할 일이 있다**. 훈련·스카우팅·게임플랜이 다음 경기에 실제로 영향을 주고, 구단주 목표가 시즌 전체에 긴장감을 준다.

### 3.2 비목표 (MVP에서 하지 않음)
- 2D/3D 경기 그래픽 애니메이션 (텍스트 중계만)
- 경기 중 실시간 플레이 콜
- 멀티플레이어 / 온라인
- 팀 로고·유니폼 이미지 (MVP는 팀 약어 + 팀 색상으로 표시)
- 모바일 전용 UI (반응형은 기본만)

## 4. 핵심 게임 루프

```
[시즌 시작]
   │
   ▼
┌─────────────── 주간 루프 (Week 1 ~ 18 + 플레이오프) ───────────────┐
│ 1. 인박스 확인   : 지난 경기 결과, 구단주 신뢰도 변화, 부상 진단            │
│ 2. 부상 관리     : 주간 부상 리포트, 훈련 참여 조절, IR·대체 선수 영입       │
│ 3. 스카우팅      : 스카우트 배정 (다음 상대 / FA 풀 / 특정 포지션)            │
│ 4. 주간 훈련     : 훈련 초점·강도 결정 (숙련도·상대 분석·상황 훈련·회복)     │
│ 5. 로스터/뎁스차트: 선발 조정, 경기 출전 명단(48인) 지정                     │
│ 6. 게임플랜      : 상대 성향 리포트 보고 전술·대응 강도 조정                 │
│ 7. 경기 시뮬     : 즉시 결과 / 빠른 중계 / 플레이별 중계 중 선택              │
│ 8. 결과 분석     : 박스스코어, 전술 효과·궁합·읽힘 리포트                     │
│ 9. 리그 진행     : 다른 경기 자동 시뮬 → 순위표·리그 기록 갱신               │
└────────────────────────────────────────────────────────────────┘
   │
   ▼
[플레이오프 → 슈퍼볼 → 시즌 요약 + 구단주 평가]  → (Post-MVP: 오프시즌 → 다음 시즌)
```

### F2. 선수 모델

#### F2-1. 포지션
QB, RB, FB, WR, TE, OT, OG, C, EDGE, DT, LB, CB, S, K, P, LS
- 좌우·세부 자리(LT/RT, LG/RG, WR X/Z/슬롯, LDE/NT, WLB/MLB, LCB/RCB/NB, FS/SS 등)는 주 포지션이 아니라 **뎁스차트 슬롯**으로 구분한다 (M0 구현).
- 선수는 **주 포지션 1개 + 보조 포지션 N개**(숙련도 %)를 가진다. 보조 포지션 배치 시 해당 숙련도만큼 능력 페널티.

#### F2-2. 능력치 (FM식 1–20 표기)
내부 계산은 연속값(1.0–20.0 float), UI 표기는 1–20 정수. 각 숫자의 의미는 **F2-5 기준표**를 따른다.

| 그룹 | 능력치 |
|------|--------|
| 신체 | 스피드, 가속, 민첩성, 근력, 점프, 지구력(스태미나) |
| 정신 | 풋볼 IQ(인지), 침착성, 결단력, 리더십, **일관성(숨김)**, **큰경기 강도(숨김)** |
| 의료(숨김) | **내구성**(1 = 유리몸, 20 = 철인), **회복력**(부상 회복 속도), **통증 내성**(부상 안고 뛸 때 성능 유지) |
| 패싱 | 송구 파워, 단거리 정확도, 중거리 정확도, 장거리 정확도, 이동 중 송구, 포켓 감각, 판단력 |
| 볼캐리 | 볼 안전성, 시야(비전), 회피, 태클 돌파 |
| 리시빙 | 캐칭, 경합 캐치, 루트 러닝, 릴리즈 |
| 블로킹 | 런 블록, 패스 블록, 리드 블록 |
| 수비 | 패스 러시(파워), 패스 러시(피네스), 블록 떨치기, 런 스톱, 태클, 추격, 맨 커버리지, 존 커버리지, 프레스, 볼 스킬 |
| 스페셜 | 킥 파워, 킥 정확도, 펀트 파워, 펀트 정확도, 리턴 |

#### F2-5. 능력치 1–20 기준표

**원칙**
1. **절대 척도**: 모든 능력치는 포지션과 무관하게 **리그 전체 기준 하나**로 매긴다. WR의 스피드 16과 CB의 스피드 16은 같은 빠르기다. 그래야 매치업 계산에서 능력치를 바로 비교할 수 있다.
2. **기준 집단**: 기술 능력치의 등급은 **그 기술을 주로 쓰는 포지션의 NFL 선수들**을 기준으로 정한다 (예: 맨 커버리지는 CB·S 기준). 해당 기술을 쓰지 않는 포지션은 자연스럽게 낮은 값이 된다 (예: OL의 캐칭 2–4).
3. **모든 능력치는 높을수록 좋다** (숨김 능력치 포함).
4. **NFL은 이미 상위 0.1%**: 10은 "평범한 사람"이 아니라 **NFL 로스터에 남을 수 있는 수준**이다.

**F2-5a. 등급 정의 (기술·정신 능력치 공통)**

| 값 | 등급 | 의미 | 기준 집단 내 대략 위치 |
|----|------|------|------------------------|

| 18–19 | 올프로 | 리그 최정상급. 매 시즌 해당 능력으로 경기를 지배 | 상위 ~3% |
| 16–17 | 프로볼 | 확실한 강점. 상대가 대비책을 세워야 하는 수준 | 상위 ~10% |

**F2-5d. 분포 검증 규칙 (데이터 산출 후 자동 점검)**
- 포지션별 **주전(뎁스 1순위)의 PR 평균이 12.5–13.5** 사이.
- 리그 전체에서 **PR 17.0 이상은 포지션당 1–3명** 수준.
- 핵심 능력치 값 20은 **리그 전체 능력치별 0–3명**.
- 기준을 벗어나면 산출 파이프라인(§7.2)의 스케일 파라미터를 조정한다.

**F2-5e. 엔진에서의 의미**
- 매치업 계산은 **능력치 차이**를 쓴다. 기본값: **차이 1점당 성공 확률 로짓 +0.12** (설정 파일에서 튜닝).
- 즉 16 대 12 매치업(차이 4)은 대등한 매치업 대비 공격 성공 확률이 대략 10–12%p 오른다. 수치는 §8.4 보정 과정에서 확정한다.

#### F2-6. 역할 (Role)

Football Manager의 "역할" 개념을 가져온다. 같은 포지션이라도 **어떤 역할이냐에 따라 중요한 능력치가 다르다**. 역할 분류는 Madden의 포지션 아키타입과 실제 NFL 스킴 용어를 참고한다.

### F4. 전술 / 플레이북 (핵심 기능)

전술은 **"팀 철학(기본 성향)" → "상황별 성향" → "상대별 게임플랜(주간 오버라이드)"** 3계층으로 구성한다. 경기 중에는 **AI 코디네이터**가 이 설정에 따라 매 플레이를 콜한다.

#### F4-3. 상황별 성향 (Situational Tendencies)
- 상황 버킷: **다운(1/2/3/4) × 남은 거리(짧음 1–3 / 중간 4–7 / 김 8+) × 필드 구역(자진영 깊숙이 / 미드필드 / 상대 진영 / 레드존 / 골라인)**
- 각 버킷에서 F4-1/F4-2 기본값 대비 **가감(override)** 설정 가능. 예: "3rd & 짧음 → 런 80%", "레드존 → 블리츠 +20%".
- UI: 히트맵 형태의 표로 편집. 대부분 사용자는 기본값만 쓰고 고급 사용자만 세부 편집.

#### F4-6. 플레이북 모델
MVP는 개별 플레이 도식 대신 **플레이 패밀리(추상화된 플레이 유형)** 로 구성한다. 모든 패밀리는 **실제 데이터 필드로 정의**해서, 실제 NFL 플레이를 같은 패밀리로 분류하고 결과 분포를 뽑을 수 있게 한다.

| 공격 플레이 패밀리 | 실제 데이터 분류 기준 |
|---------------------|-----------------------|
| 인사이드 런 / 아웃사이드 런 | 런 플레이의 run_gap·run_location (가드 사이 vs 태클 바깥) |
| QB 디자인 런 / QB 스닉 | QB 러시 중 스크램블 제외, FTN QB 스닉 표시 |
| RPO | FTN RPO 표시 |
| 스크린 | FTN 스크린 패스 표시 |
| 퀵 패스 (에어 야드 0–5) | 패스의 air_yards 구간 |
| 인터미디어트 패스 (6–15) | 〃 |
| 딥 패스 (16+) | 〃 |
| 플레이액션 숏 / 딥 | FTN 플레이액션 표시 + air_yards 구간 |

| 수비 콜 패밀리 | 실제 데이터 분류 기준 |
|----------------|-----------------------|
| Cover 0 (올아웃 블리츠) | 커버리지 타입 COVER_0 |
| Cover 1 (맨 + 딥 1) | COVER_1 |
| 2-Man | 2_MAN |
| Cover 2 | COVER_2 |
| Cover 3 | COVER_3 |
| 쿼터스 계열 (Cover 4/6/9) | COVER_4, COVER_6, COVER_9 |
| 수정자: 블리츠 (추가 러셔) | FTN 블리처 수 ≥ 1 |
| 수정자: 로디드 박스 | 박스 인원 ≥ 8 |
| 수정자: 라이트 박스 | 박스 인원 ≤ 6 |

- **상성 매트릭스**: 공격 패밀리 × 수비 콜 × 압박 여부 → 결과 분포. 초기값은 **2023–2025 실제 참여 데이터에서 직접 계산**한다 (F5-3). 수작업 튜닝은 데이터가 부족한 칸만.
- 개별 플레이(포메이션 + 컨셉, 예: "Shotgun Trips — Mesh")와 커스텀 플레이 제작은 🔜. 루트 데이터(13종)는 이때 사용.

#### F4-8. 전술 적합도 (Scheme Fit)
전술 선택이 **어떤 역할의 선수를 필요로 하는지**를 정의하고, 로스터와 전술이 맞지 않으면 손해를 보게 한다. 상세 계산은 [ENGINE_DESIGN.md §4](ENGINE_DESIGN.md).

**원리**: 별도의 궁합 점수를 곱하지 않는다. **매 플레이의 콜이 대결에 쓰이는 능력치와 가중치를 결정**하므로, 팀 전술(콜 비율)이 로스터의 강점 능력치를 자주 쓰면 궁합이 좋은 것이다.

|-----------|---------------------------|------------------|

### F5. 경기 시뮬레이션 엔진

#### F5-1. 경기 상태
쿼터, 게임 클락, 플레이 클락, 다운, 남은 거리, 볼 위치(0–100 야드), 점수, 타임아웃, 공격권, 피로도, 부상 상태.

#### F5-2. 엔진 3계층 구조
> 결과 계산·궁합·예측 가능성의 상세 수식과 초기값은 [ENGINE_DESIGN.md](ENGINE_DESIGN.md)를 따른다.


| 계층 | 역할 | 출처 |
|------|------|------|
| **① 진행 골격** | 경기 흐름·규칙: 킥오프, 공격권, 다운·거리, 시계·2분 경고·타임아웃, 무릎 꿇기, 연장전, 페널티 수락/거부 판단, 포메이션별 22명 배치, 피로·교체, 중계 로그 | **Football GM 경기 엔진을 Python으로 포팅** (약 1,500줄 규모). 결과 계산 부분만 ②③으로 교체 |
| **② 기준 분포** | "평균적인 NFL 팀끼리 이 상황에서 이 플레이 대 이 수비를 하면 어떤 결과가 나오나" | **nflverse 실제 플레이 기록** (2022–2025 pbp + 2023–2025 참여 데이터 + FTN 차팅)에서 조건부 분포 테이블 생성 |
| **③ 보정** | 두 팀 선수의 능력치 차이, 역할 적합도, 피로, 부상, 예측 가능성에 따라 ② 분포를 이동 | 자체 설계. 계수는 실제 데이터로 적합 |

**플레이 처리 흐름**
```
1. 상황 판단   : 다운/거리/필드/점수/시간 → 상황 버킷                  [① 골격]
2. 공격 콜     : 전술 3계층 + 상황 → 플레이 패밀리·퍼스넬 샘플링         [F4]
3. 수비 콜     : 전술 + 공격 퍼스넬 + 경기 중 학습된 상대 성향 → 콜 샘플링 [F5-7]
4. 선수 배치   : 뎁스차트·퍼스넬 패키지·피로 로테이션으로 22명 결정       [① 골격]
5. 압박 판정   : OL·백 블로킹 vs 러셔 → 압박 여부                        [② + ③]
6. 결과 샘플링 : (패밀리 × 수비 콜 × 압박 × 상황) 기준 분포를 능력치로 이동 [② + ③]
7. 부가 판정   : 턴오버, 페널티, 부상                                    [② + ③ + F10]
8. 상태 갱신·중계 : 시계, 다운, 점수, 피로, 기록, 텍스트                  [① 골격]
```

#### F5-3. 기준 분포와 능력치 보정

**기준 분포 테이블 (②)**
| 테이블 | 조건 | 결과 | 데이터 |
|--------|------|------|--------|
| 압박 확률 | 패스 패밀리 × 러셔 수 × 수비 콜 | 압박 여부, 색 | 참여 데이터 (압박 여부, 러셔 수), pbp |
| 패스 결과 | 패스 패밀리 × 수비 콜 × 압박 × 다운·거리 구간 | 완성, 에어 야드, YAC, INT | pbp + 참여 데이터 |
| 런 결과 | 런 패밀리 × 박스 인원 × 다운·거리 구간 | 야드 분포, 펌블 | pbp + FTN (박스 인원) |
| 특수팀 | 킥 거리 × 지붕·날씨 | FG 성공, 펀트 거리, 리턴 | pbp + 일정 (지붕·잔디) |
| 페널티 | 플레이 유형 | 페널티 종류·빈도 | pbp 페널티 기록 |

- 칸별 표본이 부족하면 **상위 칸으로 수축(shrinkage)**: 예) "딥 패스 × Cover 1 × 압박 × 3rd & 김" → 부족하면 "딥 패스 × Cover 1 × 압박"으로.
- 테이블은 `tools/`의 빌드 스크립트로 생성해 `data/baseline/`에 저장. 새 시즌 데이터가 나오면 재생성.

**능력치 보정 (③)**
- 결과를 **분위수(percentile) 이동** 방식으로 샘플링한다: 기준 분포에서 뽑을 분위수를 능력치 차이만큼 유리한 쪽으로 민다. 분포 모양은 실제 데이터 그대로 유지된다.
- 확률형 결과(완성, 압박, INT 등)는 **로짓 이동**: 능력치 차이 1점당 로짓 변화량(F2-5e)을 결과별로 따로 둔다.
- 결과별로 쓰는 능력치 조합의 **초기 구조는 Football GM의 공식**을 참고한다. 예) 색 확률 ← 패스러시 대 (패스블록 + 색 회피), 완성 ← (캐칭·오픈·정확도·시야) 대 커버리지.
- 계수는 **실제 데이터로 적합**한다: 실제 선수의 능력치(§7.2)를 넣고 실제 시즌을 시뮬레이션했을 때 실제 결과와 가장 가깝게 되도록 조정 (F5-5e).

**매치업 대결 구성**
| 대결 | 공격 측 요소 | 수비 측 요소 | 영향 |
|------|--------------|--------------|------|
| 패스 프로텍션 | OL 패스블록, RB/TE 블록, QB 포켓 감각 | 패스러시(파워/피네스), 블리츠 인원 | 압박·색 |
| 커버리지 | WR/TE 루트러닝·릴리즈·스피드 | CB/S 맨·존 커버(수비 콜에 따라 선택), 프레스 | 완성·에어 야드 분위수 |
| 송구 | QB 깊이별 정확도, 판단력, 압박 상태 | 볼스킬 | 완성·INT |
| 캐치 후 | 회피, 태클 돌파, 스피드 | 태클, 추격 | YAC 분위수 |
| 러닝 | OL 런블록, RB 비전·회피·태클돌파, FB 리드블록 | DL 블록 떨치기·런스톱, LB 태클 | 러싱 야드 분위수, 펌블 |
| 특수팀 | 킥 파워·정확도, 리턴 | 커버 유닛 | FG, 리턴 야드 |

- 선수의 **일관성(숨김)** 은 매 플레이 분위수 흔들림 폭, **큰경기 강도(숨김)** 는 플레이오프·접전 보정.

#### F5-7. 예측 가능성과 경기 중 학습
상세는 [ENGINE_DESIGN.md §6](ENGINE_DESIGN.md).

**원리**: 별도의 벌점 없이 두 경로로 대가가 생긴다.
1. **콜 대응**: 상대가 우리 성향을 학습해 맞는 콜(로디드 박스, 블리츠, 딥 존 등)을 더 자주 고른다.
2. **읽힘 효과**: 같은 콜이라도 상대가 예상한 플레이는 더 잘 막힌다. 실측상 패스가 예상될수록 패스 효율이 떨어진다 (기대 패스 확률 40% 미만 0.104 → 70% 초과 0.054 EPA).

경로 1만 있으면 실측 효율상 "항상 패스"가 정답이 된다. 두 경로를 함께 넣은 모형에서는 패스만 하는 팀의 효율이 전반 +0.033에서 후반 −0.001로 떨어졌다.

| 단계 | 내용 |
|------|------|
| 사전 믿음 | 상대 성향을 **스카우팅 기록**으로 안다: 이번 시즌 경기 기록 (1주차는 실제 2025 시즌 성향) + 리그 평균 xpass. 믿음 강도는 코디네이터 능력과 훈련 "상대 분석" 초점으로 커진다 |
| 경기 중 학습 | 상황 버킷(다운·거리·필드·점수·**퍼스넬**)별로 상대 플레이를 관측해 디리클레 방식으로 갱신 |
| 대응 | `(1 − λ) × 팀 정체성 + λ × 최선 대응` 혼합으로 콜 선택 |
| 양방향·양 팀 | 공격·수비 모두, **사용자 팀과 AI 팀 모두** 같은 규칙. 사용자는 경기 전에 `λ`와 게임플랜 범위만 정한다 (D2 유지) |

|----|----------|------|
| F5-7a | 양 팀 코디네이터의 성향 학습·대응 | ⏳ |

### F10. 부상 관리 (핵심 기능)

부상은 **발생 → 진단 → 주간 관리 → 출전 결정 → 복귀 후 관리**의 흐름으로 다룬다. 목표는 "운 나쁜 이벤트"가 아니라 **사용자가 판단하고 책임지는 관리 요소**로 만드는 것이다.

#### F10-1. 부상 발생 모델
| 요인 | 영향 |
|------|------|
| 플레이 유형 | 킥 리턴·러닝 플레이·색 상황에서 위험 증가 |
| 관여도 | 볼 캐리어, 태클러, 블로킹 충돌 선수에게 확률 집중 |
| 피로도 | 경기 내 피로 누적 시 **연조직 부상**(햄스트링, 사타구니, 종아리) 위험 증가 → 로테이션 설정(F3-4)과 연결 |
| 누적 부하 | 최근 3주 스냅 수가 많을수록 위험 증가 |
| 내구성(숨김) | 선수별 기본 위험 배율 (낮을수록 위험) |
| 나이 | 30세 이후 점진적 증가 |
| 재부상 | 복귀 후 일정 기간 같은 부위 위험 증가 (F10-6) |
| 경기장 표면 | 잔디/인조잔디 차이 (nflverse 일정의 잔디 정보) |

#### F10-2. 부상 유형 (초기 테이블, 데이터 파일로 관리)
| 부위·유형 | 심각도 범위 | 결장 기간 (예시) | 비고 |
|-----------|-------------|------------------|------|
| 타박상 (Contusion) | 경미 | 0–1주 | 경기 중 복귀 가능성 높음 |
| 발목 염좌 (Ankle sprain) | 경미–중등 | 1–4주 | 하이 앵클 스프레인은 3–6주 |
| 햄스트링 (Hamstring) | 경미–중등 | 1–4주 | 재발률 높음 |
| 사타구니 / 종아리 | 경미–중등 | 1–3주 | 피로 연관 |
| 무릎 MCL | 중등–심각 | 2–8주 | |
| 무릎 ACL | 시즌 아웃 | 시즌 종료 | Post-MVP에서 능력치 영구 손실 연결 |
| 아킬레스건 파열 | 시즌 아웃 | 시즌 종료 | 스피드 계열 영향 (Post-MVP) |
| 뇌진탕 (Concussion) | 프로토콜 | 0–3주 | F10-5 별도 절차 |
| 어깨 / 쇄골 | 경미–심각 | 1–8주 | QB 송구 능력 페널티 |
| 손 / 손가락 / 손목 | 경미–중등 | 0–4주 | 캐칭·볼 안전성 페널티, 캐스트 착용 출전 가능 |
| 갈비뼈 | 경미–중등 | 0–3주 | 통증 안고 출전 시 페널티 |
| 발가락 (Turf toe) | 경미–중등 | 1–6주 | 가속·민첩성 페널티 |
| 허리 | 경미–중등 | 0–3주 | |

- 부위별 빈도·포지션별 차이·결장 기간 분포는 **nflverse 주간 부상 리포트(과거 시즌)** 로 보정한다. 나이 효과(연 3% 증가), 부상 안고 출전 시 위험 증가(+50%), 심각한 부상 후 운동능력 저하 규칙은 **Football GM 부상 시스템**을 출발점으로 삼는다.
- 각 부상은 **예상 결장 범위**(예: "2–4주")로 진단되고, 실제 회복은 그 범위 안에서 **회복력(숨김)** 과 의료진 수준에 따라 결정된다. 사용자는 정확한 복귀일을 모른다.

#### F10-3. 주간 부상 관리 흐름
| 단계 | 내용 | 사용자 결정 |
|------|------|-------------|
| 1. 진단 | 경기 후 의료진 진단: 부위, 심각도, 예상 결장 범위 | — |
| 2. 훈련 참여 | 수·목·금 훈련 참여 상태 **DNP(불참) / Limited(제한) / Full(완전)** 결정. 참여를 줄이면 회복↑, 경기 준비도↓ | 사용자 선택 (기본값: 의료진 권고 자동 적용) |
| 3. 부상 리포트 | 금요일 **공식 부상 리포트** 공개: Out / Doubtful / Questionable. **리그 전체 공개** → 상대 부상자도 게임플랜에 반영 | — |
| 4. 출전 결정 | 경기 당일 출전 여부 결정. **강행 출전** 시 성능 페널티 + 악화·재부상 위험 표시 | 사용자 선택 |
| 5. 명단 조치 | IR 등재, 대체 선수 영입(F3-8), 연습 스쿼드 승격(F3-8b) | 사용자 선택 |

#### F10-4. 경기 중 부상
| ID | 요구사항 | 상태 |
|----|----------|------|
| F10-4a | 부상 발생 시 즉시 이탈, 뎁스차트 다음 순번 자동 투입 | ⏳ |
| F10-4b | 경미한 부상은 **경기 중 복귀 판정**: 부상 위험 정책(F4-4)에 따라 복귀 허용 여부 자동 결정 | ⏳ |
| F10-4c | 포지션 인원이 소진되면 **보조 포지션 PR**(F2-3d)이 가장 높은 선수를 긴급 투입 | ⏳ |
| F10-4d | 중계에 부상 장면·상태 업데이트 표시 ("OO, 발목 부상으로 라커룸 이동 — 복귀 불투명") | ⏳ |

#### F10-5. 뇌진탕 프로토콜
- 뇌진탕 의심 시 **해당 경기 복귀 불가**.
- 단계별 복귀 절차(휴식 → 가벼운 운동 → 훈련 복귀 → 컨택 훈련 → 출전 승인)를 **주간 단계**로 단순화해 진행.
- 사용자가 강행 출전을 선택할 수 없는 **유일한 부상 유형**.
- 시즌 중 뇌진탕이 반복되면 결장 기간 증가.

### 7.2 능력치 산출 방식
**원칙**: 실제 지표 → 포지션 내 백분위 → F2-5 기준표로 1–20 변환. 표본이 적은 선수는 **드래프트 순위·포지션 평균 쪽으로 수축**(경험적 베이즈).

| 능력치 그룹 | 주요 원천 지표 |
|-------------|----------------|
| 신체 | 컴바인 기록 (없으면 키·몸무게·드래프트 순위로 추정), 지구력 ← 스냅 점유율 |
| QB 정확도 (단·중·장) | 에어 야드 구간별 CPOE |
| QB 판단력·포켓 감각 | FTN INT성 송구 비율, QB 책임 색 비율, 압박 시 성적, 송구 시간 |
| QB 송구 파워 | NGS 에어 거리 지표 |
| RB 비전·회피·태클 돌파 | NGS 기대 대비 러싱 야드, 박스 인원별 성적 |
| 리시버 루트·릴리즈·캐칭 | NGS 분리도·쿠션, FTN 드롭 비율, 경합 캐치 성공률, 기대 대비 YAC |
| OL 패스·런 블록 | **경기 중 선수 명단 기반 회귀**: 해당 선수가 뛴 플레이의 압박률·러싱 효율을 동료·상대 효과를 제거하고 분리 (릿지 회귀) |
| 패스 러시 | 색, QB 히트, 명단 기반 압박 기여도 회귀 |
| 런 스톱·태클 | 태클·TFL, 명단 기반 러싱 허용 효율 회귀 |
| 맨·존 커버리지 | 명단 기반 패스 허용 EPA 회귀를 **맨 플레이와 존 플레이로 나눠** 각각 계산 |
| 볼 스킬 | 패스 디펜스·INT 비율 |
| 킥·펀트 | 거리별 FG 성공률, 펀트 거리·순 거리 |
| 정신 | IQ ← 경력·판단 지표 복합, 침착성 ← 승부처 대비 성적, 일관성 ← 경기별 성적 변동, 리더십 ← 경력·주전 기간 (수동 보정 허용) |
| 의료 (숨김) | 내구성 ← 과거 결장 빈도, 회복력 ← 부상별 평균 대비 복귀 속도, 통증 내성 ← Questionable 등록 후 실제 출전 비율 |

- 포지션 평가(PR) 가중치의 초기 구조는 **Football GM의 포지션별 종합 능력 계수**를 우리 능력치에 맞춰 옮겨 시작한다.
- 산출 스크립트는 **재현 가능한 파이프라인**(`tools/build_ratings.py`)으로 만들고, 결과는 CSV로 저장해 **수동 보정 파일**로 덮어쓸 수 있게 한다.
- 산출 후 **분포 검증 규칙(F2-5d)** 을 자동 점검한다.
- 2026 신인은 실적이 없으므로 컴바인 + 드래프트 순위 사전값만 사용.

### 7.4 데이터 사용 정책
- **개인 비상업 용도**로 확정 (D6). 실제 팀명·선수명·실데이터를 그대로 사용한다.
- 가공된 실데이터(`data/real/`)는 **저장소에 커밋**한다. 새 환경에서도 바로 플레이할 수 있게 하기 위함이다.
- 테스트용 **가상 샘플 리그**(`data/sample/`)도 함께 둔다. 엔진 테스트가 실데이터 변경에 흔들리지 않게 하기 위함이다.
- 로고·유니폼 이미지는 MVP 작업량 문제로 쓰지 않는다 (팀 약어 + 색상).
- Football GM에서 포팅한 코드는 `third_party/zengm/`에 원본 라이선스 전문과 출처를 함께 둔다. 이 조건 때문에 저장소는 **비공개로 유지**한다.
- nflverse 데이터와 모델 출처는 README에 표기한다.

| 데이터 파이프라인 | **nflreadpy** + polars | nflverse 공식 Python 패키지 |
| 모델 | xgboost, scikit-learn, scipy | EP·WP·xpass 재학습, 릿지 회귀, 분포 적합 |
| 테스트 | pytest + 통계 보정 테스트 | §8.3 |

> 대안: 프론트를 React(TypeScript)로 분리. UI 완성도는 높지만 초기 공수가 커서 MVP 이후 재검토.

### 8.3 품질 기준
- 단위 테스트: 규칙(다운/거리, 클락, 득점, 타이브레이커). 포팅 코드는 **원본의 테스트 케이스도 함께 포팅**한다 (Football GM 엔진 테스트, nflseedR 타이브레이커 예제).
- **실제 시즌 재현 테스트** (F5-5e): 2025 시즌을 1,000회 시뮬레이션해서 팀별 평균 득점·실점과 실제 값의 상관, 경기별 승률 예측의 정확도를 측정. 목표: 경기별 예측 정확도가 **실제 배팅 스프레드 기반 예측에 근접**.
- **통계 보정 테스트**: 동급 팀끼리 1,000경기 시뮬 → 평균 지표가 §8.4 범위 안에 있는지 검증.
- **전술 민감도 테스트**: 전술만 바꾼 두 팀으로 대량 시뮬 → 해당 지표가 기대 방향으로 유의미하게 변하는지 검증 (예: 블리츠↑ → 색↑, 빅플레이 허용↑).
- **엔진 설계 검증 테스트**: ENGINE_DESIGN §11의 T1–T9 (궁합 효과, 극단 성향 후반 하락, 최적 혼합, 프리셋 리그전, 숙련도 회복 등).
- **부상 관리 민감도 테스트**: 로테이션을 적극적으로 쓴 팀이 연조직 부상이 유의미하게 적은지, 강행 출전이 재부상을 늘리는지 검증.

## 13. 외부 소스 활용 계획

개인 용도이므로 라이선스와 무관하게 **가져올 수 있는 것은 전부 가져온다** (D14, D15). 방식은 네 가지다: **포팅**(코드를 Python으로 옮김), **데이터**(nflreadpy로 수집), **재학습**(공개된 모델 구조를 실데이터로 다시 학습), **참고**(설계 아이디어만).

## 14. 용어집

| 용어 | 설명 |
|------|------|
| 뎁스차트 (Depth Chart) | 포지션별 선수 출전 순번표 |
| 퍼스넬 (Personnel) | 공격 기준 RB·TE 수로 표기한 선수 구성. 예: 11 = RB 1, TE 1, WR 3 |
| 니켈 / 다임 | 수비에서 DB를 5명 / 6명 투입하는 패키지 |
| Cover 0/1/2/3/4 | 딥 존을 맡는 세이프티 수에 따른 커버리지 분류 |
| 블리츠 | LB/DB가 패스러시에 추가 가담 |
| 플레이액션 | 런 페이크 후 패스 |
| EPA | Expected Points Added, 플레이 전후 기대 득점 변화 |
| 레드존 | 상대 20야드 이내 |
| 바이위크 | 시즌 중 경기가 없는 휴식 주 |
| IR | Injured Reserve, 부상자 명단. 등재 시 최소 경기 수 결장 |
| 연습 스쿼드 (Practice Squad) | 53인 로스터 밖에서 훈련만 하는 선수단. 경기별 임시 승격 가능 |
| DNP / Limited / Full | 주간 훈련 참여 상태: 불참 / 제한 참여 / 완전 참여 |
| Out / Doubtful / Questionable | 경기 출전 전망: 결장 / 출전 어려움 / 출전 불투명 |
| PR (포지션 평가) | 포지션별 가중치로 계산한 종합 능력 (1–20, 소수 1자리) |
| 역할 (Role) | 같은 포지션 안에서의 세부 임무. 예: 슬롯 WR, 프레스 맨 CB |
| 전술 적합도 (Scheme Fit) | 선수 역할이 팀 전술 체계에 맞는 정도 |
| EP / WP | 기대득점 / 승리 확률. 플레이 전후 차이가 EPA / WPA |
| xpass | 상황상 보통 팀이 패스할 확률. 실제 패스 비율과의 차이가 PROE |
| CPOE | 기대 완성률 대비 실제 완성률 |
| 커버리지 타입 | Cover 0/1/2/3/4, 2-Man 등 수비 뒷공간 분담 방식 |
| 박스 인원 | 스냅 시 라인 근처(박스)에 선 수비수 수. 많을수록 런 대비 |
| 전술 숙련도 | 팀·선수가 특정 전술 영역에 익숙한 정도. 낮으면 실행력 저하 |
| 노출도 | 상대가 우리 성향을 얼마나 파악했는지 (상대 믿음이 리그 평균에서 벗어난 정도) |
| 상대 대응 강도 (λ) | 코디네이터가 팀 정체성 대신 상대 맞춤 콜을 고르는 비중 |
| 읽힘 효과 | 상대가 예상한 플레이가 같은 콜에서도 더 잘 막히는 효과 |
| 파악도 | 다른 팀 선수 능력치를 얼마나 정확히 아는지 (0–100) |
